# Screen and state map

Status: planned UI map. Updated October 7, 2026.

This map connects the approved clock and alarm mockups to the UI files proposed in [`architecture.md`](architecture.md). The new `wac/` source tree is planned and is not present yet. Links in the trace column point to the current UI or the mockup function that shows the corresponding behavior.

The mockups are visual references. Their preview buttons and state selectors help compare screens; they are not controls on the clock. Dates, times, locations, temperatures, network names, message text, selected alarm values, and solar event times shown in the previews are sample data; they do not define firmware defaults. Keep their layout and approved behavior, but obtain live values from the existing services or the saved configuration.

`settings_session` owns editable drafts; `device_config` owns defaults, validation, loading, and saving. Every Save is one all-or-nothing operation across every setting included in that action: after interruption, the device recovers either the complete previous configuration or the complete new one. Device Setup and Wi-Fi share one save group, so **Save & Restart** from Wi-Fi includes pending Device Setup changes and both succeed or fail together. Weather Location keeps its own save operation and commits the resolved location, coordinates, and timezone together. Alarm Save commits its alarm fields together without restarting. A Save applies the session's changed fields to the latest committed configuration and preserves unrelated settings. Nested Done buttons return to the parent editor without saving. Cancel discards the draft. On a save error, show failure and retain the draft for correction or retry. Do not publish partial settings or report success or restart until the complete requested save succeeds. See [save behavior](behavior-contract.md#editing-and-saving) and the [storage guarantee](storage-contract.md#each-save-is-all-or-nothing).

`ui/widgets/menu_controls.c` supplies the shared settings rows, toggles, and action buttons used by these views; it does not introduce another screen or own the saved settings.

The browser House Messages page is existing functionality and stays at [`targets/esp32-p4/main/web/messages.html`](../../targets/esp32-p4/main/web/messages.html). The `house-messages.html` panel in the gallery is an isolated local preview with sample API responses; it does not replace or change the browser page or its messaging service.

During operation, if a scheduled Night Shift mode cannot calculate its appearance because required time or location data is missing, retain the current effective day/night appearance and apply that appearance's **current configured brightness**. At startup, restore the last durably saved effective appearance; if no appearance is saved, start in the day appearance at configured Day Brightness. Off and Always On require no schedule inputs and take precedence over this fallback. Do not use an arbitrary 50% fallback. Solar calculations and physical backlight changes remain service-owned; the screens only show the resulting state and saved settings. See [Night Shift behavior](behavior-contract.md#night-shift-and-brightness).

## View-ID inventory and source coverage

The alarm proposal's `render()` map includes these production view keys: `digital`, `analog`, `forecast`, `conditions`, `message`, `device`, `device-setup`, `weather-settings`, `display-settings`, `device-settings`, `night-shift`, `night-mode`, `night-fixed`, `night-time`, `night-solar`, `night-offset`, `night-brightness`, `wifi`, `credentials`, `wifi-progress`, `settings`, `time`, `repeat`, `sound`, `alarm-sound`, `snooze`, and `snoozed`. `ringing` is rendered in its own preempting surface. Production adds the agreed `time-unavailable` view; the mockup expresses it as a clock state rather than a separate navigation key. Scan, error, warning, night, and keyboard variants are states or overlays in the grouped screens above, not missing source files.

The architecture's grouped planned files are `ui/screens/wifi.c`, `ui/screens/alarm_settings.c`, and `ui/screens/night_settings.c`; the shared picker and keyboard belong in `ui/widgets/`. The remaining planned screen paths cited above match the proposed tree in [`architecture.md`](architecture.md). These are target paths, not files already implemented in the current checkout.
